## Lời mở đầu:

Nếu bạn đã từng làm việc với JavaScript những năm trước 2015, chắc hẳn bạn không thể quên "cơn ác mộng" mang tên <code>XMLHttpRequest</code> hay cấu trúc <code>ajax</code> cồng kềnh của jQuery. Code rối rắm, callback lồng nhau (callback hell) khiến việc lấy dữ liệu từ server trở thành một cực hình.

Hãy tưởng tượng bạn đang đứng bên bờ sông, nhìn những chiếc thuyền nhỏ chở theo những thông điệp quý giá từ bờ này sang bờ kia. Trong thế giới lập trình web, **Fetch API** chính là những chiếc cầu hiện đại, thay thế cho những chiếc phà cũ kỹ XMLHttpRequest, mang theo dữ liệu một cách mượt mà và thanh thoát hơn.

Từ những ngày đầu của Ajax, khi mà việc giao tiếp với server còn phức tạp và rườm rà, đến thời đại của Fetch API - chúng ta đã chứng kiến một cuộc cách mạng thầm lặng nhưng sâu sắc. Hôm nay, chúng ta sẽ cùng khám phá nghệ thuật gọi REST API hiện đại, nơi mà mỗi dòng code không chỉ là lệnh máy tính mà còn là thơ ca của sự kết nối.

## Fetch API là gì?

### Bản chất của Fetch API

Fetch API không chỉ đơn thuần là một phương pháp để gửi HTTP request - nó là một triết lý mới trong việc xử lý giao tiếp bất đồng bộ. Nó cung cấp phương thức toàn cục <code>fetch()</code> để giúp bạn lấy tài nguyên từ mạng một cách dễ dàng và logic hơn.

Nếu <code>XMLHttpRequest</code> giống như một chiếc máy điện thoại bàn cũ kỹ với những nút bấm phức tạp, thì Fetch API như một chiếc smartphone hiện đại - đơn giản, trực quan và mạnh mẽ.

```javascript
// XMLHttpRequest - Quá khứ với những dòng code rối rắm
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/users");
xhr.onreadystatechange = function () {
  if (xhr.readyState === 4 && xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  }
};
xhr.send();

// Fetch API - Hiện tại với sự thanh lịch
fetch("/api/users")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error("Lỗi:", error));
```

### Tại sao nên dùng Fetch thay vì XMLHttpRequest?

Sự chuyển đổi từ XMLHttpRequest sang Fetch API giống như việc từ bỏ con đường đất gồ ghề để đi trên đường cao tốc mượt mà. Fetch API mang đến:

- **Promise-based**: etch sử dụng Promises, giúp xử lý các thao tác bất đồng bộ (asynchronous) sạch sẽ hơn, tránh callback hell.
- **Cú pháp gọn gàng**: Dễ đọc, dễ hiểu và "giống tiếng Anh" hơn.
- **Stream API**: Hỗ trợ xử lý dữ liệu dạng luồng (stream), hữu ích khi tải file lớn.

```javascript
// Sự đơn giản đến mê hoặc của Fetch API
const fetchUserData = async (userId) => {
  try {
    const response = await fetch(`/api/users/${userId}`);

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const userData = await response.json();
    return userData;
  } catch (error) {
    console.error("Không thể lấy dữ liệu người dùng:", error);
    throw error;
  }
};
```

## Cơ chế hoạt động: Từ Promise đến Async/Await

Bản chất của <code>fetch()</code> là trả về một **Promise**. Promise này sẽ:

- **Resolve (Thành công)**: Khi nhận được phản hồi từ server (ngay cả khi đó là lỗi 404 hay 500).

- **Reject (Thất bại)**: Chỉ khi có lỗi mạng (mất mạng, DNS lỗi) khiến request không thể thực hiện.

Tuy nhiên, việc dùng chuỗi <code>.then()</code> của Promise thuần túy đôi khi vẫn hơi dài dòng. Đó là lý do chúng ta nên kết hợp với Async/Await (được giới thiệu trong ES2017) để viết code bất đồng bộ trông giống như code đồng bộ tuần tự.
