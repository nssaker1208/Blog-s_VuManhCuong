  <!-- 1. Giới thiệu -->
  <h2 class="mt-8 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    1. Lời mở đầu
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Hãy thú thật đi, đã bao nhiêu lần bạn nhìn thấy dòng lỗi đỏ lòm này và chỉ muốn đập bàn phím?
  </p>

  <blockquote class="border-l-4 border-red-500 pl-4 italic my-6 text-gray-700 bg-red-50 py-3">
    <em>Access to fetch at 'https://api.backend.com/data' from origin 'http://localhost:3000' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.</em>
  </blockquote>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Nhiều bạn mới (và cả mình ngày xưa) thường nghĩ: <em>"Chắc code mình sai chỗ nào rồi"</em>. Sau đó, bạn google và tìm đủ mọi cách để sửa code Frontend.
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Nhưng sự thật phũ phàng là: <strong>Bạn không thể sửa lỗi CORS bằng code Frontend (JavaScript) thuần túy.</strong>
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Để hiểu tại sao, chúng ta phải quay lại cội nguồn của vấn đề: <strong>SOP</strong>.
  </p>

  <!-- 2. Same-Origin Policy -->
  <h2 class="mt-10 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    2. Nguồn gốc: Chính sách cùng nguồn (Same-Origin Policy)
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Trước khi trách CORS, hãy cảm ơn nó. Trình duyệt được sinh ra với một sứ mệnh bảo mật cao cả: <strong>Không tin tưởng bất kỳ ai.</strong>
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Mặc định, trình duyệt áp dụng chính sách <strong>Same-Origin Policy (SOP)</strong>. Chính sách này quy định rằng: Một trang web chỉ được phép gọi API (fetch/xhr) tới server nếu server đó có <strong>CÙNG NGUỒN (Same Origin)</strong> với trang web.
  </p>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    2.1. Vậy thế nào là "Cùng Nguồn"?
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Hai URL được coi là cùng nguồn khi chúng giống hệt nhau ở 3 điểm:
  </p>

  <ol class="list-decimal list-inside space-y-2 mb-6 text-gray-800" style="text-align: justify;">
    <li><strong>Giao thức (Protocol):</strong> http vs https</li>
    <li><strong>Tên miền (Domain):</strong> google.com vs facebook.com</li>
    <li><strong>Cổng (Port):</strong> 80 vs 3000</li>
  </ol>

  <div class="flex flex-col items-center my-6" style="text-align: center;">
    <img
      src="https://copilot.microsoft.com/th/id/BCO.bbb86c51-eb84-49d8-988e-23c9e30b4936.png"
      alt="Same-Origin Policy Examples"
      class="max-w-full h-auto rounded shadow-md transition-transform duration-500 ease-out hover:scale-[1.01]"
    >
    <p class="text-sm text-gray-500 mt-2" style="font-style: italic; font-weight: 600;">
      Hình 1: Bảng ví dụ về SOP. Chỉ cần lệch một chút về Port hay Protocol thôi là trình duyệt đã coi là "Người lạ"
    </p>
  </div>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    2.2. Tại sao cần SOP?
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Hãy tưởng tượng bạn vừa đăng nhập vào <code>facebook.com</code>. Trình duyệt lưu cookie đăng nhập của bạn. Sau đó, bạn lỡ bấm vào một trang web đen <code>evil.com</code>. Nếu không có SOP, trang <code>evil.com</code> có thể âm thầm gửi request đến <code>facebook.com</code> bằng cookie của bạn và đọc tin nhắn trộm. SOP ngăn chặn điều này bằng cách chặn <code>evil.com</code> gọi API sang <code>facebook.com</code>.
  </p>

  <!-- 3. CORS -->
  <h2 class="mt-10 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    3. CORS: "Tấm hộ chiếu" thông hành
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    SOP rất an toàn, nhưng quá cứng nhắc. Trong thế giới hiện đại, Frontend (React/Vue chạy ở <code>localhost:3000</code>) thường gọi API tới Backend (Node/Java chạy ở <code>localhost:8080</code> hoặc domain khác). Theo luật SOP, việc này bị cấm.
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Đó là lúc <strong>CORS (Cross-Origin Resource Sharing)</strong> ra đời.
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    CORS không phải là một lỗi. <strong>CORS là một cơ chế nới lỏng bảo mật</strong>, cho phép Server "cấp visa" cho những Domain lạ được phép truy cập vào tài nguyên của mình.
  </p>

  <div class="flex flex-col items-center my-6" style="text-align: center;">
    <img
      src="https://copilot.microsoft.com/th/id/BCO.f0549d3c-010c-4909-bc2d-1958ec430c0a.png"
      alt="CORS Flow"
      class="max-w-full h-auto rounded shadow-md transition-opacity duration-700 ease-out"
    >
    <p class="text-sm text-gray-500 mt-2" style="font-style: italic; font-weight: 600;">
      Hình 2: Trình duyệt đóng vai trò như hải quan. Khi Frontend gửi yêu cầu, Trình duyệt chặn lại hỏi Server
    </p>
  </div>

  <!-- 4. Preflight Request -->
  <h2 class="mt-10 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    4. Nguyên lý hoạt động: Câu chuyện về "Preflight Request"
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Đây là phần khiến nhiều bạn bối rối nhất. Đôi khi bạn thấy trong Network tab có 2 requests giống hệt nhau, cái đầu tiên là <code>OPTIONS</code>. Đó chính là <strong>Preflight Request</strong>.
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Trình duyệt chia các request thành 2 loại:
  </p>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    4.1. Simple Request (Yêu cầu đơn giản)
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Với các request đơn giản (GET, POST không có header lạ), trình duyệt gửi thẳng request đi.
  </p>

  <ul class="list-disc list-inside space-y-2 mb-6 text-gray-800" style="text-align: justify;">
    <li>
      <strong>Server:</strong> Trả về dữ liệu kèm header <code>Access-Control-Allow-Origin: *</code>
    </li>
    <li>
      <strong>Trình duyệt:</strong> Kiểm tra header đó. Nếu khớp, cho phép Frontend đọc. Nếu không, báo lỗi đỏ
    </li>
  </ul>

```javascript
// Simple Request Example
fetch("https://api.example.com/data")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error("CORS Error:", error));
```

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    4.2. Preflighted Request (Yêu cầu cần kiểm tra trước)
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Nếu bạn gửi request phức tạp (dùng <code>PUT</code>, <code>DELETE</code>, hoặc gửi <code>Content-Type: application/json</code>, gửi kèm Token...), trình duyệt cực kỳ cẩn thận.
  </p>

  <ol class="list-decimal list-inside space-y-2 mb-6 text-gray-800" style="text-align: justify;">
    <li>
      <strong>Bước 1 (Hỏi đường):</strong> Trình duyệt tự động gửi một request rỗng với method <strong>OPTIONS</strong>
      <br><em>"Này Server, lát nữa thằng Frontend định gửi method PUT kèm header Authorization đấy, anh có cho phép không?"</em>
    </li>
    <li>
      <strong>Bước 2 (Trả lời):</strong> Server phản hồi
      <br><em>"Ok, tôi cho phép domain đó, method đó."</em> (Status 200 hoặc 204)
    </li>
    <li>
      <strong>Bước 3 (Gửi thật):</strong> Lúc này trình duyệt mới dám gửi request <code>PUT</code> thật sự đi
    </li>
  </ol>

```javascript
// Preflighted Request Example
fetch("https://api.example.com/users", {
  method: "PUT",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer token123",
  },
  body: JSON.stringify({ name: "John" }),
})
  .then((response) => response.json())
  .then((data) => console.log(data));

// Trình duyệt sẽ tự động gửi OPTIONS request trước:
// OPTIONS https://api.example.com/users
// Access-Control-Request-Method: PUT
// Access-Control-Request-Headers: Content-Type, Authorization
```

    <img
      src="https://copilot.microsoft.com/th/id/BCO.642bb525-5594-4341-9a2f-75016b4e86a8.png"
      alt="Preflight Request Flow"
      class="max-w-full h-auto rounded shadow-md"
    >
    <p class="text-sm text-gray-500 mt-2" style="font-style: italic; font-weight: 600;">
      Hình 3: Luồng đi của Preflight Request. Nếu bước OPTIONS thất bại, request chính thức sẽ không bao giờ được gửi
    </p>
  </div>

  <!-- 5. Postman vs Browser -->
  <h2 class="mt-10 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    5. Tại sao Postman chạy được mà Browser thì không?
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Đây là câu hỏi kinh điển.
  </p>

  <ul class="list-disc list-inside space-y-2 mb-6 text-gray-800" style="text-align: justify;">
    <li>
      <strong>Postman:</strong> Là một công cụ dành cho Developer. Nó <strong>không phải là trình duyệt</strong>. Nó không quan tâm đến bảo mật người dùng, không có cookie session của ngân hàng hay Facebook. Do đó, nó <strong>bỏ qua SOP/CORS</strong> và gửi request thẳng tuột
    </li>
    <li>
      <strong>Trình duyệt:</strong> Phải bảo vệ người dùng bình thường khỏi các trang web độc hại. Nó bắt buộc phải tuân thủ luật chơi này
    </li>
  </ul>

  <div class="flex flex-col items-center my-6" style="text-align: center;">
    <img
      src="https://copilot.microsoft.com/th/id/BCO.69da04a4-6dbe-4d7c-893f-794254ee3220.png"
      alt="Postman vs Browser"
      class="max-w-full h-auto rounded shadow-md"
    >
    <p class="text-sm text-gray-500 mt-2" style="font-style: italic; font-weight: 600;">
      Hình 4: Postman giống như xe ưu tiên đi thẳng qua chốt. Trình duyệt phải dừng lại trình giấy tờ (CORS Headers)
    </p>
  </div>

  <!-- 6. Cách xử lý -->
  <h2 class="mt-10 mb-3 text-2xl md:text-3xl font-bold tracking-tight">
    6. Cách xử lý lỗi CORS (Đúng và Sai)
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Khi gặp lỗi này, đừng vội cài extension để bypass (đó chỉ là tự lừa dối bản thân thôi).
  </p>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    6.1. Cách 1: Cấu hình lại Server (Giải pháp triệt để)
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Lỗi CORS là do Server chưa cho phép Domain của bạn truy cập. Hãy bảo Backend Developer thêm các Header sau vào response:
  </p>

```http
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

  <p class="mt-4 mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Node.js (Express):
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Dùng gói <code>cors</code>:
  </p>

```javascript
// Cách 1: Allow tất cả origins (Không khuyến khích cho production)
app.use(cors());

// Cách 2: Chỉ định cụ thể origins (Khuyến khích)
app.use(
  cors({
    origin: "http://localhost:3000",
    credentials: true, // Nếu cần gửi cookies
    methods: ["GET", "POST", "PUT", "DELETE"],
    allowedHeaders: ["Content-Type", "Authorization"],
  })
);

app.get("/api/data", (req, res) => {
  res.json({ message: "CORS enabled!" });
});
```

  <p class="mt-4 mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Java (Spring Boot):
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Thêm annotation <code>@CrossOrigin</code>:
  </p>

```javascript
import org.springframework.web.bind.annotation.*;

@RestController
@CrossOrigin(origins = "http://localhost:3000")
public class ApiController {
    @GetMapping("/api/data")
    public ResponseEntity<String> getData() {
        return ResponseEntity.ok("CORS enabled!");
    }
    // Hoặc cấu hình global
    @Configuration
    public class CorsConfig {
        @Bean
        public WebMvcConfigurer corsConfigurer() {
            return new WebMvcConfigurer() {
            @Override
                public void addCorsMappings(CorsRegistry registry) {
                    registry.addMapping("/**")
                            .allowedOrigins("http://localhost:3000")
                            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                            .allowedHeaders("*")
                            .allowCredentials(true);
                }
            };
        }
    }
}
```

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    6.2. Cách 2: Dùng Proxy (Giải pháp cho Frontend Dev khi code)
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Nếu Backend không chịu sửa (hoặc đó là API của bên thứ 3), bạn có thể lừa trình duyệt bằng cách dùng Proxy.
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Nguyên lý: <code>Browser</code> → <code>Proxy Server (Cùng nguồn)</code> → <code>Real API</code>. Vì Server gọi Server thì không bị dính SOP!
  </p>

  <p class="mt-4 mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Trong React/Vite:
  </p>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Cấu hình file <code>vite.config.js</code> hoặc <code>setupProxy.js</code>:
  </p>

```javascript
// vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
    server: {
        proxy: {
            '/api': {
                target: 'https://api.backend.com',
                changeOrigin: true,
                rewrite: (path) => path.replace(/^/api/, '')
            }
        }
    }
});
```
