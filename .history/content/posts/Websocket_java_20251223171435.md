  <h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl">
    2. WebSocket là gì?
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    WebSocket không chỉ đơn thuần là một giao thức mạng - nó là một cuộc cách mạng trong cách chúng ta tư duy về giao tiếp giữa client và server. Nếu như HTTP truyền thống giống như việc gửi thư qua bưu điện - bạn gửi một lá thư (request) và chờ đợi hồi âm (response), thì WebSocket giống như một cuộc gọi điện thoại - kết nối liên tục, hai chiều, và tức thì.
  </p>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    2.1. Đặc điểm nổi bật
  </h3>

  <ul class="mb-6 space-y-2 text-gray-800 list-disc list-inside" style="text-align: justify;">
    <li>
      <strong>Kết nối liên tục (Persistent Connection):</strong> Một khi đã kết nối, nó tồn tại cho đến khi có lý do để đóng.
    </li>
    <li>
      <strong>Giao tiếp hai chiều (Full-duplex Communication):</strong> Server có thể chủ động gửi tin nhắn đến client mà không cần client yêu cầu.
    </li>
    <li>
      <strong>Overhead thấp:</strong> Không cần phải "bắt tay" lại mỗi lần giao tiếp như HTTP, WebSocket tiết kiệm băng thông đáng kể.
    </li>
    <li>
      <strong>Real-time:</strong> Độ trễ cực thấp, phù hợp cho chat, game, trading, monitoring.
    </li>
  </ul>

  <h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl">
    3. Nguyên lý hoạt động
  </h2>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    3.1. Quá trình thiết lập kết nối (WebSocket Handshake)
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Việc thiết lập kết nối WebSocket bắt đầu bằng HTTP handshake - cái bắt tay định mệnh giữa client và server.
  </p>

  <p class="mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Client gửi HTTP Upgrade Request:
  </p>

```
GET /chat HTTP/1.1
Host: localhost:8080
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13
```

<p class="mt-4 mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Server trả về 101 Switching Protocols:
  </p>

```
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=
```

  <p class="mt-4 mb-6 leading-relaxed text-gray-800" style="text-align: justify;">
    Kể từ thời điểm đó, kết nối TCP bên dưới được giữ nguyên, nhưng giao thức HTTP được thay thế bằng giao thức WebSocket. Cánh cổng giao tiếp hai chiều đã mở.
  </p>

  <h3 class="mt-6 mb-2 text-xl font-semibold">
    3.2. Vòng đời của kết nối
  </h3>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Mỗi kết nối WebSocket có vòng đời riêng với các trạng thái:
  </p>

  <ul class="mb-6 space-y-1 text-gray-800 list-disc list-inside" style="text-align: justify;">
    <li><strong>CONNECTING:</strong> Đang thiết lập kết nối</li>
    <li><strong>OPEN:</strong> Kết nối thành công, sẵn sàng giao tiếp</li>
    <li><strong>CLOSING:</strong> Đang đóng kết nối</li>
    <li><strong>CLOSED:</strong> Kết nối đã đóng hoàn toàn</li>
  </ul>

  <!-- 4. So sánh WebSocket với HTTP Polling -->
  <h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl">
    4. So sánh WebSocket với HTTP Polling
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    Trước khi có WebSocket, để mô phỏng thời gian thực, chúng ta thường dùng kỹ thuật <strong>Polling</strong> (thăm dò). Client cứ mỗi vài giây lại hỏi Server: "Có gì mới không?".
  </p>

| Tiêu chí         | HTTP Polling                   | WebSocket                   |
| ---------------- | ------------------------------ | --------------------------- |
| **Kiểu kết nối** | Gián đoạn (request/response)   | Liên tục (persistent)       |
| **Overhead**     | Cao (headers lặp lại)          | Thấp (chỉ data)             |
| **Real-time**    | Giả real-time (delay 1-5s)     | Thực sự real-time (<100ms)  |
| **Server Push**  | Không hỗ trợ                   | Hỗ trợ hoàn toàn            |
| **Băng thông**   | Lãng phí (nhiều request trống) | Tiết kiệm (chỉ gửi khi cần) |
| **Độ phức tạp**  | Đơn giản                       | Phức tạp hơn                |

  <!-- 5. STOMP Protocol -->
  <h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl">
    5. STOMP Protocol - Lớp trừu tượng trên WebSocket
  </h2>

  <p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;">
    <strong>STOMP (Simple Text Oriented Messaging Protocol)</strong> là một giao thức con chạy trên WebSocket, giúp định nghĩa cấu trúc tin nhắn rõ ràng (ví dụ: gửi đến đâu, ai nhận) thay vì chỉ gửi chuỗi dữ liệu thô. Spring Boot hỗ trợ rất tốt STOMP.
  </p>

  <p class="mb-3 font-semibold text-gray-900" style="text-align: justify;">
    Các khái niệm quan trọng trong STOMP:
  </p>

  <ul class="mb-6 space-y-2 text-gray-800 list-disc list-inside" style="text-align: justify;">
    <li>
      <strong>/topic:</strong> Destination cho các tin nhắn broadcast (pub/sub model) - nhiều subscriber nhận cùng một message
    </li>
    <li>
      <strong>/app:</strong> Prefix cho các message mà client gửi lên server
    </li>
    <li>
      <strong>Subscribe:</strong> Client đăng ký nhận tin từ một destination cụ thể
    </li>
    <li>
      <strong>Send:</strong> Client/Server gửi tin nhắn đến một destination
    </li>
  </ul>

<h3 class="mt-6 mb-2 text-xl font-semibold"> 
    6.2. Bước 2: Cấu hình WebSocket 
</h3>

<p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;"> 
    Tạo class cấu hình để kích hoạt WebSocket và định nghĩa nơi gửi/nhận tin nhắn: 
</p>

```java
package com.example.demo.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.messaging.simp.config.MessageBrokerRegistry;
import org.springframework.web.socket.config.annotation.EnableWebSocketMessageBroker;
import org.springframework.web.socket.config.annotation.StompEndpointRegistry;
import org.springframework.web.socket.config.annotation.WebSocketMessageBrokerConfigurer;

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // Định nghĩa endpoint để client kết nối (Handshake)
        // SockJS fallback cho trình duyệt không hỗ trợ WebSocket
        registry.addEndpoint("/ws-notification").withSockJS();
    }

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // /topic: Prefix cho các destination mà client SUBSCRIBE
        registry.enableSimpleBroker("/topic");

        // /app: Prefix cho các destination mà client GỬI tin lên server
        registry.setApplicationDestinationPrefixes("/app");
    }
}
```

        this.content = content;

    }

<h3 class="mt-6 mb-2 text-xl font-semibold"> 
    6.4. Bước 4: Tạo Controller để gửi thông báo 
</h3>

<p class="mb-4 leading-relaxed text-gray-800" style="text-align: justify;"> 
    Sử dụng <code>SimpMessagingTemplate</code> để server chủ động push tin nhắn đến client: 
</p>

```java
package com.example.demo.controller;

import com.example.demo.model.NotificationMessage;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.ResponseEntity;
import org.springframework.messaging.simp.SimpMessagingTemplate;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

@RestController
public class AdminNotificationController {

    @Autowired
    private SimpMessagingTemplate messagingTemplate;

    @PostMapping("/api/admin/send-notification")
    public ResponseEntity<String> sendNotification(@RequestBody String messageContent) {

        // Tạo thông báo với timestamp
        String time = LocalDateTime.now()
            .format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
        NotificationMessage notification =
            new NotificationMessage(messageContent, time);

        // Push tin nhắn đến tất cả client đang subscribe "/topic/global-notifications"
        messagingTemplate.convertAndSend(
            "/topic/global-notifications",
            notification
        );

        return ResponseEntity.ok("Notification sent successfully!");
    }
}
```

<h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl"> 
    9. Best Practices 
</h2>

<ul class="mb-6 space-y-2 text-gray-800 list-disc list-inside" style="text-align: justify;"> 
    <li> <strong>Xử lý reconnect:</strong> Client nên tự động kết nối lại khi mất kết nối </li> 
    <li> <strong>Authentication:</strong> Bảo vệ WebSocket endpoint bằng JWT hoặc session </li> 
    <li> <strong>Message validation:</strong> Validate dữ liệu trước khi gửi/nhận </li> 
    <li> <strong>Heartbeat/Ping-Pong:</strong> Gửi ping định kỳ để giữ kết nối sống </li> 
    <li> <strong>Error handling:</strong> Xử lý lỗi gracefully, thông báo cho user </li> 
    <li> <strong>Scale với Message Broker:</strong> Dùng RabbitMQ, Redis Pub/Sub cho hệ thống lớn </li> 
</ul>

<h2 class="mt-10 mb-3 text-2xl font-bold tracking-tight md:text-3xl"> 10. Kết luận </h2> 
    <p class="mb-6 leading-relaxed text-gray-800" style="text-align: justify;"> 
        WebSocket kết hợp với Spring Boot và STOMP cung cấp một giải pháp mạnh mẽ và dễ triển khai cho các ứng dụng real-time. Bạn đã học được cách thiết lập kết nối WebSocket, cấu hình STOMP, và xây dựng một hệ thống thông báo hoàn chỉnh. Điểm mạnh của WebSocket là khả năng server push chủ động, giúp giảm overhead so với HTTP Polling và mang lại trải nghiệm người dùng mượt mà, tức thì. 
    </p> 
    <p class="mb-6 leading-relaxed text-gray-800" style="text-align: justify;"> 
        Từ đây, bạn có thể mở rộng ứng dụng với các tính năng như authentication, private messaging (dùng <code>/queue</code>), hoặc tích hợp message broker như RabbitMQ để scale hệ thống lên mức enterprise. WebSocket không chỉ là công nghệ - nó là cầu nối cho những trải nghiệm số tương tác, sống động và kết nối con người với nhau trong thời đại 4.0.
