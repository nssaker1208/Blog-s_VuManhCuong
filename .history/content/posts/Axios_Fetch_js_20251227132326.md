## 1. Lời mở đầu

Trong các buổi code review hoặc phỏng vấn, mình thường xuyên nhận được câu hỏi: _"Anh ơi, tại sao dự án này mình lại cài `axios` trong khi trình duyệt đã có `fetch` rồi? Cài thêm thư viện có làm nặng app không?"_

Đây là một câu hỏi rất hay và xác đáng. Ngày xưa, khi `XMLHttpRequest` còn là nỗi ám ảnh, sự xuất hiện của `jQuery.ajax()` hay sau này là `Axios` như một vị cứu tinh. Nhưng từ khi **Fetch API** trở thành tiêu chuẩn của trình duyệt hiện đại, ranh giới giữa việc "cần" và "không cần" thư viện ngoài trở nên mờ nhạt.

Hôm nay, hãy cùng mình đặt hai ứng cử viên này lên bàn cân để xem ai mới là "chân ái" cho dự án của bạn nhé.

## 2. Tổng quan về hai đối thủ

### 2.1. Fetch API: "Hàng chính chủ"

**Fetch API** là một Web API native được tích hợp sẵn trong các trình duyệt modern. Nó được thiết kế để thay thế cho XMLHttpRequest và cung cấp một cách hiện đại hơn để thực hiện các HTTP requests.

**Đặc điểm:**

- **Native:** Không cần cài đặt thêm thư viện
- **Promise-based:** Hỗ trợ async/await
- **Streaming:** Hỗ trợ đọc response theo chunks
- **Service Worker friendly:** Hoạt động tốt trong Service Workers

**Ví dụ cơ bản với Fetch:**

```javascript
// GET request
const getData = async () => {
  try {
    const response = await fetch("https://api.example.com/users");

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const data = await response.json();
    return data;
  } catch (error) {
    console.error("Fetch error:", error);
    throw error;
  }
};

// POST request
const createUser = async (userData) => {
  try {
    const response = await fetch("https://api.example.com/users", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify(userData),
    });

    return await response.json();
  } catch (error) {
    console.error("Create user error:", error);
    throw error;
  }
};
```

### 2.2. Axios: "Vũ khí hạng nặng"

**Axios** là một thư viện HTTP client phổ biến được xây dựng dựa trên XMLHttpRequest cho browsers và http cho Node.js. Nó cung cấp nhiều tính năng mạnh mẽ mà Fetch API chưa có sẵn.

**Đặc điểm:**

- Tự động biến đổi JSON
- Xử lý lỗi HTTP tốt hơn
- Hỗ trợ Interceptors
- Hỗ trợ upload progress
- Tương thích rộng hơn (kể cả IE11)

## 3. So sánh qua Code thực tế

### 3.1. Cú pháp và xử lý JSON

Giả sử chúng ta muốn lấy danh sách user từ API.

**Với Fetch:**

```javascript
// Fetch
async function getUsers() {
  try {
    const response = await fetch("https://api.example.com/users");
    const data = await response.json(); // Phải thủ công parse JSON
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}
```

**Với Axios:**

```javascript
// Axios
import axios from "axios";

async function getUsers() {
  try {
    const response = await axios.get("https://api.example.com/users");
    console.log(response.data); // JSON đã sẵn sàng, không cần parse
  } catch (error) {
    console.error(error);
  }
}
```

### 3.2. Xử lý lỗi (Error Handling) - Điểm chí mạng

Đây là lý do lớn nhất khiến nhiều người vẫn ưu ái Axios.

- **Fetch:** Chỉ coi là "Lỗi" (reject promise) khi mất mạng hoặc lỗi DNS. Nếu server trả về 404 hay 500, Fetch vẫn coi là thành công! Bạn phải tự check thủ công.
- **Axios:** Tự động reject promise nếu status code nằm ngoài khoảng 2xx.

**Code so sánh:**

```javascript
// Fetch: Phải tự check
const res = await fetch(url);
if (!res.ok) {
  // 404, 500 sẽ chui vào đây
  throw new Error("Lỗi rồi: " + res.status);
}

// Axios: Tự động bắt
try {
  await axios.get(url);
} catch (err) {
  // 404, 500 tự động chui vào đây
  console.log(err.response.status);
}
```

## 4. Các tính năng "Ăn tiền" của Axios

### 4.1. Interceptors (Đánh chặn)

Đây là tính năng "Killer Feature". Interceptors cho phép bạn can thiệp vào request hoặc response trước khi chúng được xử lý bởi `then` hoặc `catch`.

**Use-case:** Tự động đính kèm Token vào mọi request, hoặc tự động logout khi gặp lỗi 401.

```javascript
// Axios Interceptors - Request
axios.interceptors.request.use(
  (config) => {
    // Tự động thêm token vào mọi request
    const token = localStorage.getItem("token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// Axios Interceptors - Response
axios.interceptors.response.use(
  (response) => response,
  (error) => {
    // Tự động logout khi token hết hạn
    if (error.response?.status === 401) {
      localStorage.removeItem("token");
      window.location.href = "/login";
    }
    return Promise.reject(error);
  }
);
```

Với Fetch, bạn phải viết các hàm wrapper (Higher Order Functions) bao bọc lấy hàm `fetch` gốc rất phức tạp mới làm được điều tương tự.

### 4.2. Request Timeout

- **Axios:** `axios.get(url, { timeout: 3000 })` - Quá đơn giản
- **Fetch:** Bạn phải dùng `AbortController`

```javascript
// Axios - Đơn giản
axios
  .get(url, { timeout: 3000 })
  .then((response) => console.log(response.data))
  .catch((error) => {
    if (error.code === "ECONNABORTED") {
      console.log("Request timeout!");
    }
  });

// Fetch Timeout - Khá cồng kềnh
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 3000);

try {
  const response = await fetch(url, { signal: controller.signal });
  clearTimeout(timeoutId);
  const data = await response.json();
} catch (error) {
  if (error.name === "AbortError") {
    console.log("Request timeout!");
  }
}
```

### 4.3. Upload Progress

```javascript
// Axios - Theo dõi tiến trình upload dễ dàng
axios.post("/upload", formData, {
  onUploadProgress: (progressEvent) => {
    const percentCompleted = Math.round(
      (progressEvent.loaded * 100) / progressEvent.total
    );
    console.log(`Upload: ${percentCompleted}%`);
  },
});

// Fetch - Không có API built-in cho upload progress
// Phải sử dụng XMLHttpRequest hoặc các workaround phức tạp
```

## 5. Bảng tổng kết: Ai thắng?

| Tiêu chí                 | Fetch API                    | Axios                                  |
| ------------------------ | ---------------------------- | -------------------------------------- |
| **Cài đặt**              | Có sẵn (Native)              | `npm install` (Tăng bundle size ~11kb) |
| **Cú pháp**              | Hơi dài dòng                 | Ngắn gọn, súc tích                     |
| **JSON Parsing**         | Thủ công (`.json()`)         | Tự động                                |
| **Xử lý lỗi HTTP**       | Không (Phải check `res.ok`)  | Có (Tự động reject 4xx, 5xx)           |
| **Timeout**              | Phức tạp (`AbortController`) | Đơn giản (`timeout` prop)              |
| **Interceptors**         | Không hỗ trợ native          | Hỗ trợ mạnh mẽ                         |
| **Upload Progress**      | Khó                          | Dễ (có callback `onUploadProgress`)    |
| **Request Cancellation** | `AbortController`            | `CancelToken` hoặc `AbortController`   |
| **Browser Support**      | Modern browsers only         | Hỗ trợ rộng (kể cả IE11)               |
| **Node.js Support**      | Cần polyfill                 | Native support                         |

## 6. Lời khuyên: Khi nào dùng cái nào?

### 6.1. Chọn Fetch API khi

- **Dự án nhỏ/cá nhân:** Bạn chỉ gọi vài API đơn giản, không cần cấu hình phức tạp
- **Tối ưu dung lượng:** Bạn cực kỳ quan tâm đến bundle size và không muốn gánh thêm 11kb của Axios
- **Modern Browsers:** Bạn không cần hỗ trợ IE11
- **Service Workers:** Fetch API được thiết kế tốt cho môi trường này

### 6.2. Chọn Axios khi

- **Dự án Enterprise/Lớn:** Nơi bạn có hàng trăm API endpoints
- **Cần Interceptors:** Để xử lý Authentication, Logging, Refresh Token tập trung
- **Tiện lợi là trên hết (DX):** Bạn muốn code gọn, xử lý lỗi nhất quán
- **Upload/Download với progress:** Cần theo dõi tiến trình upload/download file
- **Node.js và Browser cùng codebase:** Axios hoạt động tốt ở cả hai môi trường

## 7. Code Example thực tế

### 7.1. Setup Axios Instance

```javascript
// axiosInstance.js - Cấu hình tập trung
import axios from "axios";

const axiosInstance = axios.create({
  baseURL: "https://api.example.com",
  timeout: 10000,
  headers: {
    "Content-Type": "application/json",
  },
});

// Request interceptor
axiosInstance.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem("token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// Response interceptor
axiosInstance.interceptors.response.use(
  (response) => response.data,
  (error) => {
    if (error.response?.status === 401) {
      // Handle unauthorized
      localStorage.removeItem("token");
      window.location.href = "/login";
    }
    return Promise.reject(error);
  }
);

export default axiosInstance;
```

### 7.2. Setup Fetch Wrapper (tương tự Axios)

```javascript
// fetchWrapper.js - Cố gắng làm giống Axios
class FetchWrapper {
  constructor(baseURL) {
    this.baseURL = baseURL;
  }

  async request(endpoint, options = {}) {
    const url = `${this.baseURL}${endpoint}`;

    // Add default headers
    const headers = {
      "Content-Type": "application/json",
      ...options.headers,
    };

    // Add token if exists
    const token = localStorage.getItem("token");
    if (token) {
      headers.Authorization = `Bearer ${token}`;
    }

    try {
      const response = await fetch(url, {
        ...options,
        headers,
      });

      // Check for HTTP errors
      if (!response.ok) {
        if (response.status === 401) {
          localStorage.removeItem("token");
          window.location.href = "/login";
        }
        throw new Error(`HTTP error! status: ${response.status}`);
      }

      return await response.json();
    } catch (error) {
      console.error("Fetch error:", error);
      throw error;
    }
  }

  get(endpoint) {
    return this.request(endpoint, { method: "GET" });
  }

  post(endpoint, data) {
    return this.request(endpoint, {
      method: "POST",
      body: JSON.stringify(data),
    });
  }
}

export default new FetchWrapper("https://api.example.com");
```

## 8. Kết luận

Fetch API rất tốt, nó là nền tảng. Nhưng Axios giống như một bộ giáp Iron Man khoác lên người vậy. Với các dự án thực tế đi làm, mình vẫn khuyên dùng Axios (hoặc các thư viện tương tự như `Ky`) vì khả năng bảo trì và các tiện ích mà nó mang lại vượt xa cái giá phải trả về dung lượng.

Tuy nhiên, nếu bạn đang làm dự án nhỏ, cần tối ưu bundle size, hoặc đơn giản chỉ muốn học cách hoạt động của HTTP client từ gốc rễ, Fetch API là một lựa chọn tuyệt vời. Quan trọng là hiểu rõ trade-offs và chọn công cụ phù hợp với nhu cầu cụ thể của dự án.
