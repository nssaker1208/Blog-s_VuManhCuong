Fetch API trong JavaScript - Gọi REST API hiện đại

Hướng dẫn chi tiết sử dụng Fetch API với async/await, xử lý lỗi và Promise trong JavaScript hiện đại
December 24, 2025 · 6 phút · Vũ Mạnh Cường

Lời mở đầu:#

Nếu bạn đã từng làm việc với JavaScript những năm trước 2015, chắc hẳn bạn không thể quên “cơn ác mộng” mang tên XMLHttpRequest hay cấu trúc ajax cồng kềnh của jQuery. Code rối rắm, callback lồng nhau (callback hell) khiến việc lấy dữ liệu từ server trở thành một cực hình.

Hãy tưởng tượng bạn đang đứng bên bờ sông, nhìn những chiếc thuyền nhỏ chở theo những thông điệp quý giá từ bờ này sang bờ kia. Trong thế giới lập trình web, Fetch API chính là những chiếc cầu hiện đại, thay thế cho những chiếc phà cũ kỹ XMLHttpRequest, mang theo dữ liệu một cách mượt mà và thanh thoát hơn.

Từ những ngày đầu của Ajax, khi mà việc giao tiếp với server còn phức tạp và rườm rà, đến thời đại của Fetch API - chúng ta đã chứng kiến một cuộc cách mạng thầm lặng nhưng sâu sắc. Hôm nay, chúng ta sẽ cùng khám phá nghệ thuật gọi REST API hiện đại, nơi mà mỗi dòng code không chỉ là lệnh máy tính mà còn là thơ ca của sự kết nối.

Hình 1: Fetch API - Cánh cửa hiện đại dẫn lối vào thế giới REST API, nơi dữ liệu được truyền tải một cách thanh lịch và hiệu quả

Fetch API là gì?#

Bản chất của Fetch API#

Fetch API không chỉ đơn thuần là một phương pháp để gửi HTTP request - nó là một triết lý mới trong việc xử lý giao tiếp bất đồng bộ. Nó cung cấp phương thức toàn cục fetch() để giúp bạn lấy tài nguyên từ mạng một cách dễ dàng và logic hơn.

Nếu XMLHttpRequest giống như một chiếc máy điện thoại bàn cũ kỹ với những nút bấm phức tạp, thì Fetch API như một chiếc smartphone hiện đại - đơn giản, trực quan và mạnh mẽ.

// XMLHttpRequest - Quá khứ với những dòng code rối rắm
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/users");
xhr.onreadystatechange = function () {
  if (xhr.readyState === 4 && xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  }
};
xhr.send();

// Fetch API - Hiện tại với sự thanh lịch
fetch("/api/users")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error("Lỗi:", error));

Tại sao nên dùng Fetch thay vì XMLHttpRequest?#

Sự chuyển đổi từ XMLHttpRequest sang Fetch API giống như việc từ bỏ con đường đất gồ ghề để đi trên đường cao tốc mượt mà. Fetch API mang đến:

  • Promise-based: etch sử dụng Promises, giúp xử lý các thao tác bất đồng bộ (asynchronous) sạch sẽ hơn, tránh callback hell.
  • Cú pháp gọn gàng: Dễ đọc, dễ hiểu và “giống tiếng Anh” hơn.
  • Stream API: Hỗ trợ xử lý dữ liệu dạng luồng (stream), hữu ích khi tải file lớn.
// Sự đơn giản đến mê hoặc của Fetch API
const fetchUserData = async (userId) => {
  try {
    const response = await fetch(`/api/users/${userId}`);

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const userData = await response.json();
    return userData;
  } catch (error) {
    console.error("Không thể lấy dữ liệu người dùng:", error);
    throw error;
  }
};

Cơ chế hoạt động: Từ Promise đến Async/Await#

Bản chất của fetch() là trả về một Promise. Promise này sẽ:

  • Resolve (Thành công): Khi nhận được phản hồi từ server (ngay cả khi đó là lỗi 404 hay 500).

  • Reject (Thất bại): Chỉ khi có lỗi mạng (mất mạng, DNS lỗi) khiến request không thể thực hiện.

Tuy nhiên, việc dùng chuỗi .then() của Promise thuần túy đôi khi vẫn hơi dài dòng. Đó là lý do chúng ta nên kết hợp với Async/Await (được giới thiệu trong ES2017) để viết code bất đồng bộ trông giống như code đồng bộ tuần tự.

Hình 2: Luồng xử lý dữ liệu tuần tự khi sử dụng Async/Await, giúp code chạy từ trên xuống dưới dễ theo dõi.

Hướng dẫn thực hành (CRUD với Fetch)#

Chúng ta sẽ sử dụng một API giả lập phổ biến là JSONPlaceholder để thực hành.

GET Request (Lấy dữ liệu)#

Đây là thao tác cơ bản nhất. Mặc định fetch sẽ dùng phương thức GET.

// Định nghĩa hàm bất đồng bộ
async function getUserData() {
  try {
    // 1. Gửi request
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/users/1"
    );

    // 2. Chờ parse body sang JSON (đây cũng là một promise)
    const data = await response.json();

    console.log("User Data:", data);
  } catch (error) {
    console.error("Lỗi kết nối:", error);
  }
}

getUserData();

POST Request (Tạo mới dữ liệu)#

Khi gửi dữ liệu lên server, bạn cần thêm tham số thứ 2 vào hàm fetch để cấu hình method, headers và body.

  • Lưu ý quan trọng: Bạn phải dùng JSON.stringify() để chuyển object JavaScript thành chuỗi JSON trước khi gửi, và khai báo header Content-Type: application/json.
async function createPost() {
  const newPost = {
    title: "Học Fetch API",
    body: "Fetch API rất mạnh mẽ và dễ dùng",
    userId: 1,
  };

  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/posts", {
      method: "POST", // Phương thức
      headers: {
        "Content-Type": "application/json; charset=UTF-8", // Bắt buộc
      },
      body: JSON.stringify(newPost), // Chuyển đổi dữ liệu
    });

    const data = await response.json();
    console.log("Đã tạo bài viết:", data);
  } catch (error) {
    console.error("Lỗi:", error);
  }
}

Cái bẫy “Xử lý lỗi” (Must Read)#

Khi server trả về lỗi 404 Not Found hay 500 Server Error, Fetch KHÔNG coi đó là lỗi để nhảy vào catch. Với Fetch, miễn là server có phản hồi, thì đó là thành công (Resolve). Nó chỉ nhảy vào catch khi mất mạng hoặc DNS lỗi (Network Error).

Vậy nên, nếu bạn chỉ dùng try…catch, bạn sẽ bỏ lọt các lỗi logic.

Hình 3: Quy trình xử lý lỗi đúng chuẩn. Cần kiểm tra response.ok trước khi xử lý dữ liệu.

Code chuẩn để xử lý lỗi:

async function getDataSecurely() {
  try {
    const response = await fetch(
      "[https://api.example.com/data](https://api.example.com/data)"
    );

    // Kiểm tra thủ công: Status có nằm trong khoảng 200-299 không?
    if (!response.ok) {
      // Tự ném lỗi để nhảy xuống catch
      throw new Error(`Lỗi HTTP! Status: ${response.status}`);
    }

    const data = await response.json();
    return data;
  } catch (error) {
    // Lúc này catch mới bắt được cả lỗi Mạng lẫn lỗi HTTP
    console.error("Có biến:", error.message);
  }
}

Lời kết#

Fetch API kết hợp với Async/Await thực sự làm cho code JavaScript trở nên thanh thoát hơn rất nhiều. Chỉ cần bạn nhớ kỹ quy tắc về xử lý lỗi response.ok, bạn đã nắm chắc 80% công lực rồi.
