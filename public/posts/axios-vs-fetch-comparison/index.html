Axios vs Fetch - So sánh thư viện HTTP Client trong JavaScript

Phân tích sâu về ưu nhược điểm của Axios và Fetch API. Khi nào nên dùng thư viện ngoài, khi nào nên dùng hàng Native? Đâu là lựa chọn tối ưu cho dự án của bạn?
December 26, 2025 · 6 phút · Vũ Mạnh Cường

Chào các bạn,

Trong các buổi code review hoặc phỏng vấn, mình thường xuyên nhận được câu hỏi: “Anh ơi, tại sao dự án này mình lại cài axios trong khi trình duyệt đã có fetch rồi? Cài thêm thư viện có làm nặng app không?”

Đây là một câu hỏi rất hay và xác đáng. Ngày xưa, khi XMLHttpRequest còn là nỗi ám ảnh, sự xuất hiện của jQuery.ajax() hay sau này là Axios như một vị cứu tinh. Nhưng từ khi Fetch API trở thành tiêu chuẩn của trình duyệt hiện đại, ranh giới giữa việc “cần” và “không cần” thư viện ngoài trở nên mờ nhạt.

Hôm nay, hãy cùng mình đặt hai ứng cử viên này lên bàn cân để xem ai mới là “chân ái” cho dự án của bạn nhé.

1. Tổng quan về hai đối thủ#

Fetch API: “Hàng chính chủ”#

Fetch API là một Web API native được tích hợp sẵn trong các trình duyệt modern. Nó được thiết kế để thay thế cho XMLHttpRequest và cung cấp một cách hiện đại hơn để thực hiện các HTTP requests.

  • Đặc điểm:
  • Native: Không cần cài đặt thêm thư viện
  • Promise-based: Hỗ trợ async/await
  • Streaming: Hỗ trợ đọc response theo chunks
  • Service Worker friendly: Hoạt động tốt trong Service Workers

Ví dụ cơ bản với Fetch:#

// GET request
const getData = async () => {
  try {
    const response = await fetch("https://api.example.com/users");

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const data = await response.json();
    return data;
  } catch (error) {
    console.error("Fetch error:", error);
    throw error;
  }
};

// POST request
const createUser = async (userData) => {
  try {
    const response = await fetch("https://api.example.com/users", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify(userData),
    });

    return await response.json();
  } catch (error) {
    console.error("Create user error:", error);
    throw error;
  }
};

Axios: “Vũ khí hạng nặng”#

Axios là một thư viện HTTP client phổ biến được xây dựng dựa trên XMLHttpRequest cho browsers và http cho Node.js. Nó cung cấp nhiều tính năng mạnh mẽ mà Fetch API chưa có sẵn. Nghĩa là một thư viện HTTP Client bên thứ 3. Bản chất nó vẫn chạy trên XMLHttpRequest ở trình duyệt và http module ở Node.js, nhưng được bọc lại với nhiều tính năng tiện ích (Syntactic Sugar).

Hình 1: Hãy tưởng tượng Fetch như một con dao sắc bén, gọn nhẹ. Còn Axios là một con dao đa năng Thụy Sĩ với đủ thứ đồ chơi đi kèm.

2. So sánh qua Code thực tế#

Nói lý thuyết mãi cũng chán, hãy nhìn vào code.

2.1. Cú pháp và xử lý JSON#

Giả sử chúng ta muốn lấy danh sách user từ API.

Với Fetch: Bạn phải qua 2 bước await. Một để lấy response, một để parse body thành JSON.

// Fetch
async function getUsers() {
  try {
    const response = await fetch(
      "[https://api.example.com/users](https://api.example.com/users)"
    );
    const data = await response.json(); // Phải thủ công parse JSON
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}

Với Axios:
Axios tự động biến đổi JSON cho bạn. Kết quả trả về nằm gọn trong property data.

// Axios
import axios from "axios";

async function getUsers() {
  try {
    const response = await axios.get(
      "[https://api.example.com/users](https://api.example.com/users)"
    );
    console.log(response.data); // JSON đã sẵn sàng, không cần parse
  } catch (error) {
    console.error(error);
  }
}

2.2. Xử lý lỗi (Error Handling) - Điểm chí mạng#

Đây là lý do lớn nhất khiến nhiều người (trong đó có mình) vẫn ưu ái Axios.

  • Fetch: Chỉ coi là “Lỗi” (reject promise) khi mất mạng hoặc lỗi DNS. Nếu server trả về 404 hay 500, Fetch vẫn coi là thành công! Bạn phải tự check thủ công.

  • Axios: Tự động reject promise nếu status code nằm ngoài khoảng 2xx.

Hình 2: Luồng xử lý lỗi. Fetch đòi hỏi bạn phải viết thêm logic if (!res.ok) thủ công, trong khi Axios tự động ném lỗi vào block catch.

Code so sánh:

// Fetch: Phải tự check
const res = await fetch(url);
if (!res.ok) {
  // 404, 500 sẽ chui vào đây
  throw new Error("Lỗi rồi: " + res.status);
}

// Axios: Tự động bắt
try {
  await axios.get(url);
} catch (err) {
  // 404, 500 tự động chui vào đây
  console.log(err.response.status);
}

3. Các tính năng “Ăn tiền” của Axios#

Nếu chỉ vì cú pháp ngắn hơn một chút, có lẽ Axios không phổ biến đến thế. Sức mạnh thực sự của nó nằm ở những tính năng nâng cao mà Fetch làm rất cực khổ.

3.1. Interceptors (Đánh chặn)#

Đây là tính năng “Killer Feature”. Interceptors cho phép bạn can thiệp vào request hoặc response trước khi chúng được xử lý bởi then hoặc catch.

Use-case: Tự động đính kèm Token vào mọi request, hoặc tự động logout khi gặp lỗi 401.

Hình 3: Cơ chế Interceptor hoạt động giống như chốt bảo vệ. Mọi request đi ra hoặc đi vào đều phải qua chốt kiểm tra này.

Với Fetch, bạn phải viết các hàm wrapper (Higher Order Functions) bao bọc lấy hàm fetch gốc rất phức tạp mới làm được điều tương tự.

3.2. Request Timeout

  • Axios: axios.get(url, { timeout: 3000 }) - Quá đơn giản.
  • Fetch: Bạn phải dùng AbortController.
// Fetch Timeout - Khá cồng kềnh
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 3000);

await fetch(url, { signal: controller.signal });

4. Bảng tổng kết: Ai thắng?#

Để dễ hình dung, mình tóm tắt lại trong bảng sau:

Tiêu chí Fetch API Axios
Cài đặt Có sẵn (Native) npm install (Tăng bundle size ~11kb)
Cú pháp Hơi dài dòng Ngắn gọn, súc tích
JSON Parsing Thủ công (.json()) Tự động
Xử lý lỗi HTTP Không (Phải check res.ok) Có (Tự động reject 4xx, 5xx)
Timeout Phức tạp (AbortController) Đơn giản (timeout prop)
Interceptors Không hỗ trợ native Hỗ trợ mạnh mẽ
Upload Progress Khó Dễ (có callback onUploadProgress)

5. Lời khuyên: Khi nào dùng cái nào?#

Chọn Fetch API khi:

  • Dự án nhỏ/cá nhân: Bạn chỉ gọi vài API đơn giản, không cần cấu hình phức tạp.
  • Tối ưu dung lượng: Bạn cực kỳ quan tâm đến bundle size và không muốn gánh thêm 11kb của Axios.
  • Modern Browsers: Bạn không cần hỗ trợ IE11 (dù Axios hỗ trợ IE tốt hơn).

Chọn Axios khi:

  • Dự án Enterprise/Lớn: Nơi bạn có hàng trăm API endpoints.
  • Cần Interceptors: Để xử lý Authentication, Logging, Refresh Token tập trung.
  • Tiện lợi là trên hết (DX): Bạn muốn code gọn, xử lý lỗi nhất quán và không muốn viết đi viết lại logic parse JSON.

6. Kết luận#

Fetch API rất tốt, nó là nền tảng. Nhưng Axios giống như một bộ giáp Iron Man khoác lên người vậy. Với các dự án thực tế đi làm, mình vẫn khuyên dùng Axios (hoặc các thư viện tương tự như Ky) vì khả năng bảo trì và các tiện ích mà nó mang lại vượt xa cái giá phải trả về dung lượng.
