WebSocket với Java Spring Boot

Xây dựng Real-time Notification System với WebSocket API và Spring Boot
December 21, 2025 · 9 phút · Vu Manh Cuong

Lời Mở Đầu#

Hãy tưởng tượng bạn đang ngồi trong một quán cà phê yên tĩnh, nhấm nháp tách cà phê đen đậm đà, và đột nhiên điện thoại rung lên với một thông báo: “Bạn có một tin nhắn mới”. Cảm giác ấy - sự kết nối tức thì, không cần phải chờ đợi hay làm mới trang - chính là linh hồn của WebSocket.

Trong kỷ nguyên số hiện đại, người dùng mong đợi sự phản hồi tức thì. Việc phải nhấn nút “Refresh” (F5) để xem có thông báo mới hay không đã trở nên lỗi thời và gây trải nghiệm tồi tệ. Hãy tưởng tượng Facebook, Shopee hay ứng dụng ngân hàng của bạn không tự động hiện thông báo mới mà bạn phải tự tải lại trang?

Đây là lúc công nghệ Real-time (thời gian thực) phát huy tác dụng. Và trong thế giới Java, sự kết hợp giữa Spring Boot và WebSocket là một giải pháp mạnh mẽ, chuẩn mực để giải quyết vấn đề này.

Bài viết này sẽ hướng dẫn bạn từ lý thuyết nền tảng đến thực hành xây dựng một hệ thống thông báo thời gian thực đơn giản.

Hình 1: WebSocket - Cây cầu kết nối thời gian thực giữa server và client, như những dây thần kinh truyền tín hiệu tức thì

WebSocket Là Gì?#

Bản Chất Của WebSocket#

WebSocket không chỉ đơn thuần là một giao thức mạng - nó là một cuộc cách mạng trong cách chúng ta tư duy về giao tiếp giữa client và server. Nếu như HTTP truyền thống giống như việc gửi thư qua bưu điện - bạn gửi một lá thư (request) và chờ đợi hồi âm (response), thì WebSocket giống như một cuộc gọi điện thoại - kết nối liên tục, hai chiều, và tức thì.

// Một kêt́ nôí WebSocket đơn giản như hơi thở của cuộc sôńg @Component
public class WebSocketLifecycle {
    // Khi kêt́ nôí được thiêt́ lập - như khoảnh khăć hai trái tim gặp nhau @EventListener
    public void handleWebSocketConnectListener(SessionConnectedEvent event) {
        logger.info("Một linh hôǹ mới đã kêt́ nôí: {}", event.getUser().getName());
    }
    // Khi kêt́ nôí bị đóng - như lúc chia ly @EventListener
    public void handleWebSocketDisconnectListener(SessionDisconnectEvent event) {
        logger.info("Tạm biệt một người bạn: {}", event.getUser().getName());
    }
}

Hình 2: So sánh WebSocket và HTTP - Từ mô hình hỏi-đáp đơn lẻ đến cuộc đối thoại liên tục

Đặc điểm nổi bật của WebSocket#

WebSocket mang trong mình những đặc điểm làm nên sự khác biệt:

  • Kết nối liên tục (Persistent Connection): Như tình bạn thật sự, một khi đã kết nối, nó tồn tại mãi mãi cho đến khi có lý do để chia tay.
  • Giao tiếp hai chiều (Full-duplex Communication): Server có thể chủ động gửi tin nhắn đến client mà không cần client yêu cầu - giống như người bạn tốt luôn biết khi nào bạn cần được quan tâm.
  • Overhead thấp: Không cần phải “bắt tay” lại mỗi lần giao tiếp như HTTP, WebSocket tiết kiệm băng thông như một người bạn hiểu ý.

Hình 3: Các đặc điểm nổi bật của WebSocket - Kết nối liên tục, hai chiều và hiệu quả

Nguyên lý hoạt động#

Quá trình thiết lập kết nối#

Việc thiết lập kết nối WebSocket giống như một nghi thức thiêng liêng, bắt đầu bằng HTTP handshake - cái bắt tay định mệnh giữa client và server.

Client Request:
GET /chat HTTP/1.1
Host: localhost:8080
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13

Client gửi một HTTP Request thông thường đến Server, nhưng trong header có chứa thông tin đặc biệt: Upgrade: websocket và Connection: Upgrade. Điều này giống như nói: “Chào Server, tôi muốn nâng cấp giao tiếp này lên WebSocket, bạn đồng ý không?”.

Server Response:
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

Nếu Server hỗ trợ WebSocket, nó sẽ trả về mã 101 Switching Protocols (Chuyển đổi giao thức).

Kể từ thời điểm đó, kết nối TCP bên dưới được giữ nguyên, nhưng giao thức HTTP bị thay thế bằng giao thức WebSocket. Cánh cổng giao tiếp hai chiều đã mở.

Hình 4: Quá trình handshake WebSocket - Cái bắt tay định mệnh mở ra cánh cửa giao tiếp thời gian thực

Vòng đời của một kết nối#

Mỗi kết nối WebSocket có vòng đời riêng, như một câu chuyện tình với đầy đủ khởi đầu, phát triển, và kết thúc:

  • CONNECTING: Khoảnh khắc chờ đợi đầy hồi hộp
  • OPEN: Niềm vui của sự kết nối thành công
  • CLOSING: Sự chuẩn bị cho lời chia tay
  • CLOSED: Kết thúc một hành trình

So sánh WebSocket với các phương pháp truyền thống#

Trước khi có WebSocket, để mô phỏng thời gian thực, chúng ta thường dùng kỹ thuật Polling (thăm dò). Client cứ mỗi vài giây lại hỏi Server: “Có gì mới không?”.

Tiêu chí HTTP Polling WebSocket
Kết nối Gián đoạn (như tin nhắn SMS) Liên tục (như cuộc gọi)
Overhead Cao (headers lặp lại) Thấp (chỉ data)
Realtime Giả real-time Thực sự real-time
Server Push Không hỗ trợ Hỗ trợ hoàn toàn
Độ phức tạp Đơn giản Phức tạp hơn

Hình 5: So sánh HTTP Polling và WebSocket - Từ sự gián đoạn đến dòng chảy liên tục

Thực hành: Xây dựng Notification System với Spring Boot#

Chúng ta sẽ xây dựng một ứng dụng đơn giản: Server có một endpoint để admin gửi thông báo, và tất cả các client đang kết nối sẽ nhận được thông báo đó ngay lập tức trên giao diện web.

Chúng ta sẽ sử dụng STOMP (Simple Text Oriented Messaging Protocol) trên nền WebSocket. STOMP giúp định nghĩa cấu trúc tin nhắn rõ ràng (ví dụ: gửi đến đâu, ai nhận) thay vì chỉ gửi chuỗi dữ liệu thô. Spring Boot hỗ trợ rất tốt STOMP.

Bước 1: Cài đặt Dependency

Tạo một dự án Spring Boot và thêm dependency spring-boot-starter-websocket vào file pom.xml:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-websocket</artifactId>
</dependency>

Bước 2: Cấu hình WebSocket (The Broker)

Tạo một class cấu hình để kích hoạt tính năng WebSocket và định nghĩa nơi gửi/nhận tin nhắn.

src/main/java/com/example/demo/config/WebSocketConfig.java

package com.example.demo.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.messaging.simp.config.MessageBrokerRegistry;
import org.springframework.web.socket.config.annotation.EnableWebSocketMessageBroker;
import org.springframework.web.socket.config.annotation.StompEndpointRegistry;
import org.springframework.web.socket.config.annotation.WebSocketMessageBrokerConfigurer;

@Configuration
@EnableWebSocketMessageBroker // 1. Kích hoạt WebSocket server
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // 2. Định nghĩa endpoint để client kết nối đến (Handshake)
        // Chúng ta dùng SockJS để fallback nếu trình duyệt không hỗ trợ WebSocket thuần
        registry.addEndpoint("/ws-notification").withSockJS();
    }

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // 3. Cấu hình Message Broker (Người môi giới tin nhắn)

        // /topic: Tiền tố cho các đích đến (destination) mà client sẽ ĐĂNG KÝ NHẬN (Subscribe).
        // Phù hợp cho mô hình pub/sub (broadcast thông báo).
        registry.enableSimpleBroker("/topic");

        // /app: Tiền tố cho các đích đến mà client sẽ GỬI tin nhắn LÊN server.
        // (Ví dụ: client gửi chat thì gửi vào /app/chat)
        registry.setApplicationDestinationPrefixes("/app");
    }
}

Bước 3: Tạo Model cho Thông báo

Một class Java đơn giản đại diện cho nội dung thông báo.

src/main/java/com/example/demo/model/NotificationMessage.java

package com.example.demo.model;

public class NotificationMessage {
    private String content;
    private String timestamp;

    public NotificationMessage() {
    }

    public NotificationMessage(String content, String timestamp) {
        this.content = content;
        this.timestamp = timestamp;
    }

    // Getters and Setters...
    public String getContent() { return content; }
    public void setContent(String content) { this.content = content; }
    public String getTimestamp() { return timestamp; }
    public void setTimestamp(String timestamp) { this.timestamp = timestamp; }
}

Bước 4: Tạo Controller để gửi thông báo (Server-side Push)

Đây là phần quan trọng nhất của hệ thống thông báo. Chúng ta cần một cách để server chủ động gửi tin nhắn đến các client đã đăng ký vào một “topic” cụ thể. Spring cung cấp SimpMessagingTemplate để làm việc này.

Chúng ta sẽ tạo một REST Controller bình thường để giả lập việc admin kích hoạt một sự kiện, sự kiện này sẽ kích hoạt việc gửi thông báo WebSocket.

src/main/java/com/example/demo/controller/AdminNotificationController.java

package com.example.demo.controller;

import com.example.demo.model.NotificationMessage;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.ResponseEntity;
import org.springframework.messaging.simp.SimpMessagingTemplate;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

@RestController
public class AdminNotificationController {

    // Inject SimpMessagingTemplate để gửi tin nhắn WebSocket
    @Autowired
    private SimpMessagingTemplate messagingTemplate;

    // Endpoint HTTP thường để admin gọi (ví dụ qua Postman)
    @PostMapping("/api/admin/send-notification")
    public ResponseEntity<String> sendNotification(@RequestBody String messageContent) {

        // Tạo đối tượng thông báo
        String time = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
        NotificationMessage notification = new NotificationMessage(messageContent, time);

        // CHỦ ĐỘNG ĐẨY tin nhắn xuống tất cả client đang subscribe "/topic/global-notifications"
        messagingTemplate.convertAndSend("/topic/global-notifications", notification);

        return ResponseEntity.ok("Notification sent successfully via WebSocket!");
    }
}

Bước 5: Tạo Client (Frontend) để nhận thông báo

Chúng ta cần một trang HTML đơn giản sử dụng thư viện SockJS và Stomp.js để kết nối và nhận dữ liệu.

Tạo file src/main/resources/static/index.html:

<!DOCTYPE html>
<html>
  <head>
    <title>Real-time Notifications</title>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/sockjs-client/1.5.1/sockjs.min.js"></script>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/stomp.js/2.3.3/stomp.min.js"></script>
    <style>
      #notifications-area {
        border: 1px solid #ccc;
        height: 300px;
        overflow-y: scroll;
        padding: 10px;
        background: #f9f9f9;
      }
      .notify-item {
        margin-bottom: 10px;
        padding: 5px;
        background: #e1f5fe;
        border-radius: 4px;
      }
      .time {
        font-size: 0.8em;
        color: #666;
      }
    </style>
  </head>
  <body>
    <h2>Hệ thống thông báo Real-time</h2>
    <div id="notifications-area">
      <p>Đang chờ thông báo...</p>
    </div>

    <script>
      var stompClient = null;

      function connect() {
        // 1. Kết nối đến endpoint đã định nghĩa trong Spring Boot
        var socket = new SockJS("/ws-notification");
        stompClient = Stomp.over(socket);

        stompClient.connect({}, function (frame) {
          console.log("Connected: " + frame);
          document.getElementById("notifications-area").innerHTML =
            "<p>Đã kết nối! Sẵn sàng nhận tin.</p>";

          // 2. Đăng ký (Subscribe) để nhận tin từ "/topic/global-notifications"
          stompClient.subscribe(
            "/topic/global-notifications",
            function (notification) {
              // Khi có tin nhắn mới, hàm này sẽ được gọi
              showNotification(JSON.parse(notification.body));
            }
          );
        });
      }

      function showNotification(message) {
        var notificationsArea = document.getElementById("notifications-area");
        var newItem = document.createElement("div");
        newItem.className = "notify-item";
        newItem.innerHTML = `<strong>Thông báo mới:</strong> ${message.content} <br/> <span class="time">${message.timestamp}</span>`;

        // Thêm thông báo mới lên đầu
        notificationsArea.insertBefore(newItem, notificationsArea.firstChild);
      }

      // Tự động kết nối khi tải trang
      connect();
    </script>
  </body>
</html>

Bước 6: Chạy thử nghiệm

  1. Chạy ứng dụng Spring Boot (cổng mặc định 8080).

  2. Mở trình duyệt, truy cập http://localhost:8080. Bạn sẽ thấy trạng thái “Đã kết nối!”. Mở thêm 1 tab nữa để thấy hiệu quả broadcast.

  3. Sử dụng Postman (hoặc curl) để gửi một HTTP POST request giả lập hành động của Admin:

  • URL: http://localhost:8080/api/admin/send-notification

  • Method: POST

  • Body (raw/text): Chào mừng đợt giảm giá Black Friday!

  1. Kết quả: Ngay lập tức, trên cả hai tab trình duyệt của bạn sẽ xuất hiện thông báo mới mà không cần tải lại trang.

Điểm chính cần nhớ:

  • WebSocket vs HTTP: WebSocket là kết nối hai chiều bền vững, tối ưu cho real-time hơn là HTTP Polling.
  • STOMP: Giao thức con giúp định tuyến tin nhắn dễ dàng (dùng /topic, /app).]
  • SimpMessagingTemplate: Công cụ đắc lực trong Spring để server chủ động đẩy tin nhắn xuống client bất cứ lúc nào.
